# Service Rules

- A service is the one place that talks to one outside system: `app/Services/<System>/<System>Service.php`, e.g. `NekoBtService`, `GitHubService`, `HostBridgeService`. Actions and jobs call it; nothing else sends it requests.
- Its public methods are the questions the app asks (`getTorrents(NekoBtSearchData)`), take DTOs or scalars and return DTOs. URLs, query names, timeouts and parsing stay inside it. A DTO maps the system's answer itself: with `MapInputName` (dot paths for nested values) when the names differ, or in a static `from<System>(array $data)` when values need converting (`NekoBtTorrentData::fromNekoBt()`). A system's word for "not known" (MyAnimeList's `N/A` score, qBittorrent's 100-day eta, VLC's length of 0) becomes null in the DTO's `prepareForPipeline()`, so the app never sees it and no getter has to clean it. Numbers a system uses for an enum live on the enum (`HasNekoBtNumber`). When several systems fill one shared DTO, each maps its own data first and converts that (`NekoBtMediaData::toShowTemplate()`), so the shared one knows none of them. Only real parsing, such as a web page, goes in a final sibling parser class that only the service uses (`MalAnimePageParser`). Map what the system sends; add a check for missing or odd data only once it really happened.
- Data that is the system's own (a torrent site's listings, its levels and tags) keeps the system's shape: its own DTOs (`App\Dtos\NekoBt`), enums (`NekoBtLevel`), endpoint (`nekobt-torrents`) and resource. Don't force two systems into one shape that fits neither. A shared interface fits only when every system answers in the app's own terms: `ShowTemplateSource` (a show from a page link) is one, implemented by each site's service and listed in `ResolveShowTemplateSourceAction`, which picks the one for a link. Sources report every title they know, their own first; `GetShowTemplateAction` decides which to keep.
- A system without a usable public API is read from its web pages: a parser reads the HTML with PHP's `Dom\HTMLDocument` and CSS selectors (`MalAnimePageParser`).
- A failure the caller can't fix throws a domain exception (an `ApiException`, such as `TorrentSiteUnavailableException`, 502), after a `Log::warning` that says what the system answered.
- Settings of the system (base URL, timeout) live in `config/<system>.php`. A system the user runs themselves, such as their qBittorrent, gets its address and login from settings instead: its connector reads them itself, so callers never pass a connection. Values that aren't saved yet (the setup wizard's) are the connector's optional argument, used by a method of their own (`testConnection($values)`). A system that isn't always the same one gets its connection when the service is made: `new VlcService($vlcConnection)` is one VLC window, with its own port and password. Secrets are `secret` settings, stored encrypted and never sent to the frontend.
- Services are adapters only: no models, actions or HTTP layer classes, except a connector reading `Setting` (`tests/Unit/ArchitectureTest.php`). Application policy belongs to the calling action. An outside site that shouldn't be asked the same again and again is remembered with `RemembersJson`: it keeps the raw answer, never a DTO, for `cache_seconds` from that system's config, and nothing when the request fails. A service holds no state: it makes a new connector for each request, and the connector logs in by itself. Reuse a session or a connection only once it's shown to be a problem.
- Requests go through Saloon (`saloonphp/saloon` with its Laravel plugin), never Laravel's `Http` client (`tests/Unit/ArchitectureTest.php`). Next to the service: `<System>Connector.php`, extending `ServiceConnector` (base URL, auth including any login, headers, timeout) and one `Requests/<Verb><Thing>Request.php` per call (method, endpoint, query or body), whose constructor takes typed, named values, never a payload or options array. A request does one thing: two calls that differ in meaning are two requests (`EnqueueRequest`, `PlayRequest`). Both are `final` and only the service uses them. The service sends with `(new XConnector)->send(new XRequest(...))`, catches `FatalRequestException` for "didn't answer", and checks the answer's status and shape. `LenientJsonResponse` reads a non-JSON body (a bot check's HTML) as no JSON values instead of throwing.
- Tests fake the system with `Saloon::fake([...])`, keyed by connector, request class or URL pattern (`'nekobt.test/*'`), feeding a saved real answer from `tests/Fixtures/<system>/` through `MockResponse::make(...)`, trimmed to the parts the app reads and formatted (indented JSON or HTML, never a one-line dump) so a reviewer can read it. `Saloon::fake([])` stops unexpected requests. `tests/Pest.php` has the helpers: `saloonConnectionRefused()`, `saloonSequence([...])`, and `saloonSent()` / `saloonSentUrls()` to check what was sent.
